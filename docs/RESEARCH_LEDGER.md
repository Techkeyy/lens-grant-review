## Product assumptions and proof needed

| Assumption | Why it matters | Proof that closes it |
| --- | --- | --- |
| Small charities possess usable timesheets, spending records, activity logs, and draft reports for two grants | Without records Lens cannot reconcile anything | Obtain or construct from real templates an anonymized realistic corpus; ideally review with a grant manager |
| Claims can be linked to canonical source records | False matches create misleading findings | Test near-duplicate names, dates, and receipts; show exact provenance and `needs review` where identity is uncertain |
| Cross-grant allocation is a useful distinguishing case | Single-report evidence check is crowded | Show one overallocated source and one valid proportional split in the product; research current competitors before marketing a uniqueness claim |
| Zetaris adds meaningful cross-source access | Sponsor score requires real use | Documented smoke query `SELECT 1 AS one`, list a database/table, then run a live join/query over at least two Lens evidence sources; capture response and failure handling |
| Meterless can store or structure the review state | World Model may be a specification rather than a ready hosted runtime | Prove an actual write, read after refresh/restart, and correction history before calling it integrated |
| Any AI component is genuinely agentic | The event asks for an agent that does real work | Show real tool selection/investigation across sources, with bounded decisions and trace; a one-shot summary alone is insufficient |
| User data can be handled safely | Timesheets and receipts contain sensitive data | Define access, storage, retention, redaction, and demo data policy before using real documents |
